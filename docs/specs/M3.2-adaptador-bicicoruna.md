# M3.2 — Adaptador BiciCoruña

- Estado: implementada
- Rama: `feat/M3.2-adaptador-bicicoruna`
- Referencia: `docs/ROADMAP.md` (M3), `docs/sources/bicicoruna.md`

## Problema y objetivo

Convertir la API SmartCity de BiciCoruña (79 estaciones, una petición) en `StationStatus` validado para la capa `bike`.

## Alcance

Dentro: `packages/adapters/bicicoruna/` (`fetch`, `parse` puro, fixture, tests).

Fuera: ingesta/BD (M3.5), cambios en `packages/schema` (eléctricas, nombre, estado no caben: ver riesgos).

## Diseño

- `Adapter<StationStatus>` con `id: "bicicoruna"`, `intervalMs: 60_000`.
- `fetch`: un GET a `getAssets` con `httpGetJson`; devuelve `{ fetchedAt, body }` donde `fetchedAt` es la hora de la petición (la fuente trae `dateModified` vacío), de modo que `parse` sigue siendo puro.
- `parse`: `id` = `BikeHireDockingStation.id`; `[lat, lon]` invertido respecto a GeoJSON; `bikes` = `availableBikeNumber`; `docks` = `freeSlotNumber`; `ts` = `fetchedAt`.
- Se descartan estaciones sin id, con coordenadas no numéricas o fuera de A Coruña, o con contadores ausentes/no enteros/negativos. Cuerpo que no es array: error (formato cambiado).
- `status` distinto de `working`: `bikes` y `docks` a 0 (valores distintos no observados aún).

## Criterios de aceptación

- [x] 79 estaciones válidas mapean a `StationStatus` que pasa `StationStatusSchema`.
- [x] Vacío, campo ausente y coordenadas inválidas cubiertos sin romper.
- [x] Tests sin red.

## Plan de pruebas

Vitest contra `fixtures/getAssets.json` (2 estaciones reales recortadas de la nota de fuente) y casos sintéticos.

## Riesgos y decisiones

- El contrato no cubre bicis eléctricas, nombre ni estado: no se tocó el schema (`strictObject`, sin `meta`). Cambio de contrato pendiente si se quieren (skill `contract-change`).
- `ts` es la hora de la petición, no del dato.
- Atribución a la fuente aceptada por el humano (2026-11-18).
