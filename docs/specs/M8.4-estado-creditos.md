# M8.4 — Estado y créditos

- Estado: implementada
- Rama: `feat/M8.4-estado-creditos`
- Referencia: `docs/ROADMAP.md` (M8.4), `docs/sources/*.md` (licencias y atribuciones)

## Problema y objetivo

Las fuentes exigen atribución y la web debe decir con honestidad qué datos están al día. Hoy la atribución del mapa vive en el control de MapLibre y el estado de las capas solo aparece cuando algo falla. M8.4 añade un panel **«Estado y créditos»**: estado de cada fuente según nuestra API y las atribuciones y licencias requeridas, con enlaces.

## Alcance

Dentro:

- Enlace discreto «Estado y créditos» en la esquina inferior izquierda de la UI que abre un `<dialog>` modal (foco atrapado, Escape cierra, el foco vuelve al enlace).
- Estado por fuente desde `GET /api/v1/health` de nuestra API (URL derivada de la del stream con `resolveHealthUrl`; el navegador nunca llama a terceros). Estados: cargando, error (con «Reintentar»), sin API (sin URL de stream, p. ej. producción sin `VITE_LIVE_URL`) y listo. Mismo vocabulario que las capas (`SourceState` de `live/source-status.ts`): `ok → live`, `degraded → delayed`, `down → nodata`; más «no activa» (la fuente no figura en `sources`, p. ej. iTranvías sin permiso) y «sin estado en vivo» (mapa base y Catastro, datos estáticos).
- Atribución y licencia por fuente, tomadas de `docs/sources/*.md`. Si la nota no documenta licencia, se muestra «Licencia pendiente de confirmar» (las licencias son decisión humana; no se inventa ningún término).
- i18n gl/es/en. Los nombres propios de fuentes y las fórmulas de atribución son literales de las notas de fuente y no se traducen.
- Carga diferida del estado (chunk propio); ver Diseño.
- Mock de `/api/v1/health` en el servidor de desarrollo (`dev:mock`) para verificar sin API.
- Enlace en el README (sección Créditos).

Fuera:

- Cambios en `apps/api` o en `packages/schema` (el contrato de `/health` ya trae todo lo necesario).
- Elegir licencias o textos de atribución (decisión humana, M1/M8.7): se transcribe lo documentado.
- Fuentes sin adaptador en uso (REData, EEA/Calidade do Aire) y Natural Earth: no se muestran hasta que existan en la UI.

## Diseño

- Reparto por presupuesto (JS diferido 557,2/560 KB): los **créditos** (catálogo + diálogo, `status/credits.ts`, `status/sources.ts`) viven en el JS inicial —obligación legal, se ven al instante y sin red; el JS inicial pasa de 11,4 a 13,2 KB frente a 250—; el **estado** (`status/start.ts` + `status/model.ts`) es un chunk diferido que se descarga al abrir el panel. Un primer intento con todo en un chunk diferido dejaba el presupuesto en 560,1 KB (fallo); este reparto lo deja en 558,2 KB.
- `status/sources.ts`: catálogo de datos (atribución, URL, licencia o `null` = pendiente, `unverified` si se declara sin texto leído). Ids de `source_health`: `bicicoruna`, `meteogalicia`, `portus`, `openmeteo-air`, `itranvias`, `gtfs-tranvias` + `bus-schedule`, `opensky`, `aisstream`. Textos de uso/nota: claves `credits.use.<key>` y `credits.note.<key>`.
- `status/link.ts`: botón discreto (móvil: bajo el selector de modo; escritorio: abajo a la izquierda); crea el panel al primer clic.
- `status/model.ts`: `parseHealthReport` (tolerante, sin zod) y `deriveRows` (puro, reutiliza `worstState`). `ok → live`, `degraded → delayed`, `down → nodata`.
- Tiempos con `formatAgo(lastSuccessAt, report.ts)` (relativos al reloj del servidor). Se consulta en cada apertura (sin sondeo) y se cancela al cerrar.
- `live/dev/mock-health.ts` + ruta en `vite/mock-live-plugin.mjs`.
- Accesibilidad: `<dialog>` nativo, `aria-labelledby`, lista semántica, marca de estado con forma además de color (relleno = al día/retrasada, aro = sin datos, aro discontinuo = sin consultar o no activa, guion = sin estado en vivo), región `aria-live` educada solo para «listo/error».

## Criterios de aceptación

- [x] El enlace abre el panel y es operable con teclado; Escape cierra y devuelve el foco.
- [x] Con API: cada fuente muestra estado y «última lectura hace X»; con respuesta 503 válida también.
- [x] Estados cargando, error (reintento) y sin API cubiertos y probados.
- [x] Cada fuente de `docs/sources` en uso muestra atribución y enlace; la licencia sin documentar dice «pendiente de confirmar»; Open-Meteo muestra «Open-Meteo.com (datos CAMS)» CC BY 4.0, uso no comercial.
- [x] Sin cadenas fijas visibles: claves gl/es/en (paridad testeada).
- [x] JS diferido ≤ 560 KB gzip (`pnpm perf:bundle`) y JS inicial ≤ 250 KB.
- [x] Capturas `docs/design/capturas/m8-4-*.png` (390×844 y 1440×900).

## Riesgos y decisiones

- Presupuesto de JS diferido muy ajustado (margen 1,8 KB tras M8.4): futuras tareas de UI deben medir con `pnpm perf:bundle`. Sin dependencias nuevas.
- Licencias «pendientes de confirmar» (Portus, OpenSky, aisstream, iTranvías, GTFS, BiciCoruña `RISP_AC` sin texto leído): visibles hasta que el humano las cierre en M1/M8.7; al hacerlo basta editar `status/sources.ts`.
- La licencia CC BY-SA 4.0 de MeteoGalicia («compartir igual») y la compatibilidad ODbL del Catastro siguen como riesgo residual documentado en sus notas.
