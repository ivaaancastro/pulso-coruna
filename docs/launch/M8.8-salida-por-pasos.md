# M8.8 — Salida por pasos: Cerrado → Local → Global

**Responsable: humano.** Checklist sin ejecutar nada: el agente no despliega, no contrata ni activa claves. Detalle técnico de despliegue: `docs/deploy.md`; fuentes y licencias: `docs/launch/M8.7-contacto-institucional.md`.

## Resumen

| Paso        | Audiencia                                      | Qué se activa                                                                       | Puerta para pasar al siguiente                                             |
| ----------- | ---------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **Cerrado** | Solo tú (y revisores invitados)                | Pila completa en el VPS, sin anunciar; grabando datos                               | ≥ 7 días estables; presupuestos de M8.3 cumplidos                          |
| **Local**   | Coruña: contactos, prensa local, comunidad dev | Mismo servicio, enlace compartido en círculos locales; fuentes con licencia cerrada | Licencias de las fuentes activas cerradas; ≥ 14 días sin incidentes graves |
| **Global**  | Público (portfolio, redes, post técnico)       | Misma instalación; difusión amplia                                                  | Respuestas M8.7 archivadas o plan B; coste real medido                     |

No hay cambio de infraestructura entre pasos: lo que cambia es la audiencia y qué fuentes están encendidas.

## 1. Paso «Cerrado»

**Se activa:** `docker compose -f infra/deploy/docker-compose.yml up -d --build` (db, ingest, api, backup, caddy, web). Solo fuentes sin dudas legales: GTFS estimado, BiciCoruña, MeteoGalicia, aire (EEA/Open-Meteo), Catastro/OSM en teselas; Portus/OpenSky/aisstream según §3 de M8.7; iTranvías **apagada**.

**Checklist**

- [ ] `docker compose ps`: todo `Up`, `db` healthy; `https://DOMINIO` carga con certificado válido.
- [ ] `infra/deploy/scripts/health.sh`: cada fuente activa en `ok`, filas creciendo y `rows_written_total` subiendo.
- [ ] `curl https://DOMINIO/api/v1/health` responde 200; estado de cada capa coherente (con iTranvías apagada, `bus` vacío es lo esperado).
- [ ] Lighthouse y presupuestos en el dominio real; 0 peticiones a terceros (pestaña Red).
- [ ] Móvil real medido (M8.3).
- [ ] Backup manual (`docker compose exec backup sh /scripts/backup.sh`) y **prueba de restauración** (`restore.sh --db verif`).
- [ ] Puertos: 5432 no publicado (`ss -ltn` desde fuera/escáner).
- [ ] Panel «Estado y créditos» en gl/es/en: atribuciones correctas.

**Métricas de salud (vigilar a diario):** estado de fuentes (`ok/degraded/down`, edad del dato), fallos consecutivos y latencia por fuente; filas/día (~0,5 M); espacio de disco y tamaño de BD; RAM/CPU del VPS; logs `retención fallida`; errores 429/503 de la API; conexiones WS simultáneas y rechazos por límite por IP; renovación del certificado.

## 4. Criterio de vuelta atrás

| Señal                                                                  | Acción                                                                                                                                                   |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Una fuente pide cese o bloquea la IP                                   | Apagar su variable `*_ENABLED` y `docker compose up -d ingest`; la capa se atenúa con «sin datos». Responder por escrito; borrar histórico si lo exigen. |
| Fuente caída > 24 h o respuestas malformadas                           | Dejar que la web degrade (estado «sin datos»); si es crítica, apagarla. No reintentar más agresivamente.                                                 |
| BD o disco > 85 % / ingesta en bucle de reinicios                      | Reducir `RETENTION_RAW_DAYS` (mín. 7), revisar `docker system df`; si persiste, volver al paso anterior (retirar enlaces).                               |
| Picos de 429/503, RAM agotada o coste por encima del presupuesto       | Bajar límites (`API_WS_MAX_PER_IP`, `API_REPLAY_MAX_PER_IP`), poner Caddy en mantenimiento o retirar difusión.                                           |
| Error de datos engañoso (p. ej. buses simulados mostrados como reales) | Corregir y mostrar aviso; volver a «Cerrado» hasta verificar.                                                                                            |
| Incidente de seguridad (clave expuesta)                                | Rotar clave de inmediato; `SHIP_ID_SALT` **no** se rota salvo compromiso grave (rompe ids). Cortar DNS/puertos si hace falta.                            |

Volver atrás = retirar el enlace/anuncio y, si procede, `docker compose stop` del servicio afectado. **Nunca** `docker compose down -v` en producción (borra `pgdata` y `caddy_data`). Restaurar con `restore.sh` desde backup.
