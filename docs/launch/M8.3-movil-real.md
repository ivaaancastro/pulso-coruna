# M8.3 — Medición en móvil real antiguo

**Responsable: humano** (necesita un dispositivo físico). El agente no puede ejecutar nada de esto. Presupuestos: `docs/ROADMAP.md` (sección «Presupuestos de rendimiento»). El CI solo vigila regresiones (ADR-0011); el presupuesto real se mide aquí.

## Qué hace falta del humano

- [ ] Un móvil **antiguo o de gama baja** (iOS: iPhone con 4+ años, p. ej. 8/X/XR; Android: gama baja con ≤ 3 GB de RAM y ≥ 4 años). Anota modelo, SO y versión del navegador.
- [ ] Cable de datos (imprescindible para Safari Web Inspector; recomendable en Android) y un Mac/PC en la misma red Wi-Fi.
- [ ] Batería ≥ 80 %, ahorro de energía desactivado, brillo fijo al 50 %, sin apps en segundo plano, sin bloqueo automático de pantalla.

## 1. Preparar el servidor

Mide siempre la **build de producción** (`vite preview`), nunca `vite dev`. Con datos en vivo reales necesitas la API (local o VPS, ver `docs/deploy.md`); sin ella la web usa el mock/fixtures: vale para fps y peso, no para el WebSocket.

```bash
# en el repo, rama develop actualizada
pnpm install
# VITE_LIVE_URL se fija en el build; omítela para medir sin API
VITE_LIVE_URL=ws://<IP-LAN-DEL-PC>:3000/api/v1/stream pnpm --filter @pulso/web build
pnpm --filter @pulso/web exec vite preview --host 0.0.0.0 --port 4174 --strictPort
```

Comprueba que se sirve `coruna.pmtiles` (`infra/tiles/README.md`); sin él no hay mapa base.

## 2. Conectar el dispositivo

| Vía                         | Cuándo                                | Cómo                                                                                                                                                                                               |
| --------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LAN**                     | Móvil y PC en la misma Wi-Fi          | Abre `http://<IP-LAN-DEL-PC>:4174` en el móvil. HTTP en LAN no es «contexto seguro»: el service worker/PWA **no** se activan.                                                                      |
| **Android + `adb reverse`** | Quieres `localhost` (contexto seguro) | USB con depuración activada; `adb reverse tcp:4174 tcp:4174` y abre `http://localhost:4174`. Si usas API local, añade `adb reverse tcp:3000 tcp:3000` (y `VITE_LIVE_URL=ws://localhost:3000/...`). |
| **Túnel HTTPS**             | Necesitas HTTPS real (SW, PWA)        | Túnel de tu elección al puerto 4174 (p. ej. `cloudflared tunnel --url http://localhost:4174`). Decisión del humano (instala software y expone la build); ciérralo al terminar.                     |
| **VPS ya desplegado**       | Medida más fiel                       | Abre el dominio (paso «Cerrado» de M8.8); incluye latencia real y Caddy.                                                                                                                           |

Inspección remota:

- **Android (Chrome):** Opciones de desarrollador → Depuración USB. En el PC, `chrome://inspect/#devices` → «Inspect». Da Performance, Network, Lighthouse y consola.
- **iOS (Safari):** móvil: Ajustes → Safari → Avanzado → Inspector web. Mac: Safari → Ajustes → Avanzado → «Mostrar funciones para desarrolladores»; menú Desarrollo → [iPhone] → página. Pestañas Cronología, Red, Consola.

## 3. Escena y procedimiento

**Escena media (idéntica en todas las pasadas):** cámara por defecto tras la intro, todas las capas activas (bus, bici, viento, barcos, aviones, aire, marea), modo En vivo, `?lang=es`, vertical. Segunda pasada opcional: Reproducir a 600×.

Por pasada: cierra la pestaña, reinicia el navegador, borra datos del sitio, **carga en frío**, espera a que acabe la intro (`map:intro-end`) y mide 60 s estables. Haz **3 pasadas** y anota la mediana. Deja 5 min de reposo entre pasadas para no medir con el equipo caliente (salvo la prueba térmica).

## 4. Qué medir y cómo

| Métrica                 | Presupuesto                                           | Cómo medirlo                                                                                                                                                                                                   |
| ----------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| fps con todas las capas | media ≥ 58, p5 ≥ 50                                   | Snippet de abajo en la consola remota (60 s). Chrome: Performance → grabar 10 s → «Frames». Safari: Cronología → fotogramas por segundo.                                                                       |
| Primer fotograma mapa   | < 2,0 s                                               | Consola: `performance.getEntriesByName('map:first-frame')[0].startTime` (carga en frío).                                                                                                                       |
| LCP                     | < 2,5 s (umbral de Lighthouse CI)                     | Chrome remoto: Lighthouse (Mobile, Performance) o Performance → Web Vitals. En iOS no hay LCP nativo: anota «n/d» y usa `map:first-frame`.                                                                     |
| INP                     | < 100 ms                                              | Chrome: Performance grabando mientras tocas una entidad, cambias de modo y arrastras la línea temporal (panel «Interactions»). Alternativa: `PerformanceObserver` de tipo `event` con `durationThreshold: 16`. |
| Peso transferido        | JS inicial < 250 KB gzip; mapa/deck diferido < 560 KB | Pestaña Red, carga en frío con caché desactivada: total y JS inicial vs. diferido. Contrasta con `pnpm perf:bundle` en el PC.                                                                                  |
| Peticiones a terceros   | 0                                                     | Pestaña Red: toda fila con origen distinto al propio es un fallo (fuentes tipográficas, teselas, analítica…).                                                                                                  |
| Degradación automática  | si < 45 fps durante 3 s                               | Anota si se activa (menos partículas/estelas) y en qué segundo. En un móvil muy antiguo es esperable, pero debe actuar y dejar ≥ 30 fps.                                                                       |
| Batería (opcional)      | —                                                     | % al inicio y a los 10 min; Android: `adb shell dumpsys batterystats`; iOS: Ajustes → Batería (uso por app).                                                                                                   |
| Temperatura (opcional)  | —                                                     | Android: `adb shell dumpsys battery` (décimas de °C) al inicio y a los 10 min. iOS: sensación al tacto y aviso térmico si aparece (subjetivo).                                                                 |

Snippet de fps (consola remota; no modifica la app):

```js
(async () => {
  const dts = [];
  let last = performance.now();
  const end = last + 60_000;
  await new Promise((done) => {
    const tick = (t) => {
      dts.push(t - last);
      last = t;
      t < end ? requestAnimationFrame(tick) : done();
    };
    requestAnimationFrame(tick);
  });
  const fps = dts.map((d) => 1000 / d).sort((a, b) => a - b);
  const avg = 1000 / (dts.reduce((a, b) => a + b, 0) / dts.length);
  console.log({ avg: avg.toFixed(1), p5: fps[Math.floor(fps.length * 0.05)].toFixed(1) });
})();
```

## 6. Criterio de aceptación (M8.3 → `[x]`)

- La mediana de 3 pasadas cumple todos los presupuestos obligatorios **o** cada incumplimiento está documentado con causa y decisión firmada por el humano (p. ej. «p5 = 41 fps; la degradación actúa en 2 s; aceptado»).
- Peticiones a terceros = 0 en todas las pasadas, sin excepción.
- Resultados guardados en el repo con modelo y versión. Los números de móvil real del README (M8.6) salen **solo** de aquí.
- Si un presupuesto falla sin justificación aceptable: abrir tarea de optimización, no marcar M8.3 y volver a medir.
